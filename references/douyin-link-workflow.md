# 抖音链接批处理工作流

## 触发条件

用户一次发送1至3条抖音分享链接，并要求提取视频、分析、本地化或生成提示词时使用。若只发送链接而未提供 brief，沿用当前任务中已明确的游戏名和产品术语；没有可用 brief 时仅追问会改变产品落点的关键信息。

## 输入

至少包含：

- 1至3条抖音链接
- 目标游戏或产品名

可选包含：

- 画风与目标时长
- 角色图及替换关系
- 核心卖点和固定台词
- 场景本地化方向

## 自动处理

### 1. 建立任务目录

使用日期与任务名创建独立目录：

```text
抖音下载_YYYY-MM-DD/
├── manifest.json
├── 01/
│   ├── source-url.txt
│   ├── video.mp4
│   └── analysis/
├── 02/
└── 03/
```

不要覆盖同名旧任务；目录存在时增加时分秒后缀。

### 2. 下载与校验

运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/process-douyin-links.ps1 `
  -Links "链接1","链接2","链接3" `
  -OutputDirectory "D:\任务目录"
```

脚本依次尝试普通下载、Chrome 登录状态和 Edge 登录状态。下载后使用 `ffprobe` 校验时长、画幅、视频轨和音轨，并标准化为 H.264 + AAC MP4。

若自动下载器无法解析：

1. 使用联网或浏览器工具打开短链接并取得最终作品页。
2. 在页面 DOM 或媒体网络响应中定位真实视频地址。
3. 下载媒体文件到对应编号目录。
4. 使用 `ffmpeg` 标准化后重新抽帧。

不要使用要求用户上传账号密码的第三方下载站。

### 3. 抽帧

每条视频运行 `scripts/analyze-video.ps1`。必须查看：

- `metadata.json`：时长、画幅、帧率、音轨
- `opening.jpg`：前15秒与前三秒钩子
- `overview.jpg`：完整结构和场景变化
- `scene-frames`：切镜、角色位置和展示机制

出现以下情况时补充每0.5秒或1秒抽帧：

- 动作顺序不确定
- 角色进出画方向不确定
- 固定视角与移动镜头难以判断
- 台词与动作对应关系不清楚
- 开头和玩法展示之间存在快速转场

### 4. 单条分析

每条视频独立记录：

1. 前3秒钩子
2. 开头、发展、转折、落点
3. 角色数量、站位和动作关系
4. 场景是否保留以及本地化后的场景
5. 镜头类型、运动方向和切镜节奏
6. 台词功能及需要保留或替换的重点句
7. 可迁移的玩法卖点
8. 目标时长和是否需要压缩至15秒以内

分析结论必须来自视频画面和音轨，不根据标题补写剧情。

### 5. 本地化

- 保留结构、节奏、镜头机制和动作因果。
- 用目标游戏真实角色、道具、场景和玩法术语替换表层元素。
- 删除竞品名称、角色名、专属UI和品牌标识。
- 台词保持短、口语化和功能一一对应。
- 每条链接生成独立提示词，不跨视频复用剧情元素。
- Seedance 单条生成时，将核心内容压缩到15秒以内；需要动作参考的视频片段裁至15.2秒以内。

### 6. 输出

严格按链接顺序输出。每条包含：

1. 3至5条分析结论
2. 【画面风格】
3. 【场景】
4. 【角色】
5. 【具体内容】
6. 【正向提示词】
7. 【镜头设计思路】

剧情类的每个分镜必须包含时间轴、运镜、景别、场景、画面、具体内容和配音/音效。

## 失败隔离

`manifest.json` 为每条链接记录：

- `status`
- `source_url`
- `video_path`
- `analysis_path`
- `error`

一条失败时继续处理其余链接。最终只对失败项说明：

- 失败发生在跳转、下载、转码还是抽帧
- 已尝试哪些自动恢复方法
- 下一步可以由联网或浏览器工具自动完成什么
