# 巨物Boss三视图、首帧与视频提示词工作流

## 适用场景

用户提供三类参考图：

- Boss：最终巨大化并展示大招。
- 宠物：与主角并肩前进。
- 主角：从背后跟随视角冲向Boss。

目标是一次完成：

```text
参考图 -> 三份三视图 -> 9:16首帧 -> 6秒视频提示词 -> 标准文件夹
```

## 输入识别

单组任务接受三张图片；批量任务接受多个编号文件夹。优先识别文件名 `boss`、`宠物`、`主角` 或 `角色`。无法从名称判断时查看图片确认，不根据文件扩展名或顺序猜测。

每组开始前记录三类角色的稳定视觉特征：

- Boss：物种、轮廓、主色、标志器官、武器或技能媒介。
- 宠物：物种、体型、主色、头部与尾部特征。
- 主角：发型、主服装轮廓、帽子或背包等背面识别点。

## 第一步：生成三视图

为Boss、宠物和主角分别生成一张独立三视图，不能把三名角色放进同一张图。

每张三视图必须满足：

1. 横向画布，纯净暖白工作室背景。
2. 从左到右依次为正面、右侧面、背面。
3. 三个视图全身完整、同一基线、相同尺寸，不裁切。
4. 正交视图，避免透视夸张和动作姿势。
5. 保留原图颜色、花纹、配饰、身体结构与比例。
6. 日系游戏三渲二概念设定图，轻描边、两层赛璐璐阴影。
7. 不生成文字、方向标签、水印、额外角色或额外配饰。

原图只有一个角度时，根据可见结构谨慎补全侧面和背面；不擅自改变物种、服装主题或核心轮廓。

## 第二步：自动匹配场景

根据Boss、宠物和主角共同的视觉语义选择一个场景。场景应支持一条明确的前进路径与远端Boss站位。

可参考以下映射，但不要机械套用：

| 角色特征 | 场景方向 | 大招方向 |
|---|---|---|
| 冰、白毛、长角 | 冰川湖谷、雪原峡谷 | 冰柱、冻结冲击波 |
| 雷、电翼、金色鸟类 | 雷鸣高原、云顶石路 | 振翼雷暴、外侧雷柱 |
| 花、鹿、粉色植物 | 花海、镜湖、樱谷 | 花瓣环、低空花潮 |
| 火、岩石、橙红巨兽 | 火山峡谷、熔岩高台 | 熔岩震地、火焰冲击 |
| 森林、虎猿、部落 | 雨林神庙、古代石阶 | 双拳震地、尘雾冲击 |
| 狼、利爪、冷色 | 银月针叶峡谷 | 十字挥爪、寒风爪痕 |
| 水生、珊瑚、蓝色 | 海底遗迹、潮汐海岸 | 水幕、潮汐波纹 |

场景名称应具体，例如“极光冰川湖谷”，不要只写“冰原”。

## 第三步：生成9:16首帧

首帧是静态对峙构图，不在绘画提示词中混入奔跑、蓄力、释放大招和结尾等连续动作。

### 构图硬规则

1. 竖版9:16。
2. Boss正面位于画面上半部，视觉高度约占全画面48%-52%，宽度约占65%-70%。
3. Boss必须保持完整轮廓；翅膀、角、尾巴、武器、利爪不得裁切。
4. Boss最高点上方保留约8%-10%的干净天空或背景，作为后期标题安全区。
5. 主角位于画面下方中部偏右，宠物位于主角左侧，二者靠近但不重叠。
6. 主角与宠物均为严格完整背面，头部、躯干和脚尖正对Boss；不得出现脸、眼睛、嘴、鼻口或侧脸。
7. 宠物尤其要检查方向。四足宠物需要后脑、背部、臀部和尾巴朝向镜头，头部指向Boss。
8. 主角和宠物下方保留约10%-12%的干净道路或地面前景，不贴底边。
9. 双方之间保留长距离道路、桥梁、石阶或踏石，形成明确纵深。
10. 使用压缩长焦透视：距离显得很远，但Boss不能因此变小。

### 首帧提示词结构

```text
# 首帧绘画提示词

【画风】
【场景】
【人物】
【具体内容】
【正向提示词】
【负向提示词】
```

【具体内容】只描述画面在这一帧中的静态状态。动态动作只放入后续视频提示词。

## 第四步：生成6秒视频提示词

视频以生成的首帧作为第一帧，默认总时长约6秒。除非用户另行指定，不使用逐秒分镜，改用连续动作描述。

### 主体动作

- 镜头始终位于主角背后，沿唯一道路平稳向前跟随。
- 主角和宠物从开场到结尾持续向Boss奔跑或前进。
- 二者保持严格背面、固定方向、稳定间距和左右位置。
- 不安排回头、抬头特写、压低身体、闪避、跳跃、停步蓄力等额外动作。
- Boss保持原地，不向主角冲刺，不改变巨物比例。

### Boss大招

Boss在前半段原地聚集能量，结尾完成一次完整、可读的大招动作：

```text
技能媒介亮起 -> 明确蓄力 -> 一次完整肢体动作 -> 环境响应 -> 终局展示
```

大招必须来自Boss自身特征，例如翅膀振击、巨剑挥砍、双拳震地、利爪交叉斩、长角冻结或花瓣衣袖展开。特效分布在道路两侧或Boss周围，中央奔跑路线保持清晰，不遮挡三个角色。

### 视频提示词结构

```text
# 6秒视频生成提示词

【画面风格】
【场景】
【角色】
【具体内容】
【正向提示词】
【镜头设计思路】
```

首帧绘画提示词和视频提示词不能混写。首帧只描述静态构图；视频提示词必须包含主角宠物前进、背后跟随镜头与Boss结尾大招。

## 第五步：交付目录

保留用户原文件夹名称。每个交付文件夹至少包含且统一命名为：

```text
主角三视图.png
宠物三视图.png
boss三视图.png
首帧图片.png
完整提示词.txt
```

`完整提示词.txt` 按顺序包含完整的首帧绘画提示词和6秒视频生成提示词。使用UTF-8编码。可保留输入参考图，但交付检查只以以上五个文件为必备项。

批量处理时每个输入文件夹独立生成，不得把不同文件夹的角色、场景或提示词混用。某组失败时继续处理其他组，最后单独补做失败组。

## 质量检查

生成三视图后检查：

- 三个角度是否齐全、全身完整、同一角色。
- 主色、花纹、配饰和身体结构是否继承正确。

生成首帧后必须目视检查：

- Boss是否足够大，并占据上半幅主体位置。
- Boss最高点与画面顶部是否有安全距离。
- 主角和宠物是否完整背对Boss，尤其宠物不能侧对。
- 主角和宠物是否靠近，底部是否留有前景。
- 场景是否存在连续可奔跑路径。

生成提示词后检查：

- 首帧部分是否误写连续动作。
- 视频部分是否明确主角与宠物全程向前。
- Boss是否原地完成一次完整大招。
- 运镜是否只有背后连续跟随，没有多余复杂切换。
- 是否包含标准五个交付文件，TXT是否为完整内容。
